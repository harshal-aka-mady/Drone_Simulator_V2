PUBLISHING DRONE TRAINER V2 ON GITHUB
=====================================

This "github" folder is the whole repo, ready to push. It is a DOWNLOADS +
LANDING PAGE repo, not the source code. That is on purpose:

  - The game's source and its protection stay off GitHub, so no one can read or
    fork the actual game. The builds are locked and encrypted, and Advanced needs
    a serial, exactly as you wanted.
  - The big installers do NOT go in the repo (GitHub blocks files over 100 MB and
    warns over 50 MB). They go as "Release" downloads instead. The README's
    download buttons already point to the latest release.

WHAT IS IN THIS FOLDER (push all of it)
  README.md          The landing page GitHub shows (with the screenshots).
  LICENSE            All rights reserved, free to use, not open source.
  .gitignore         Keeps installers, source and licensing-private off the repo.
  screenshots/       9 images used by the README.

WHAT NOT TO ADD (the .gitignore already blocks these)
  - Anything from licensing-private (signing key, serial lists) - NEVER.
  - The .exe, .dmg, .tgz source - these are either Release assets or stay private.

STEP 1 - CREATE THE REPO
  On github.com: New repository.
    Name:        drone-trainer-v2   (or voltairtech-drone-trainer)
    Description: India's RPTO drone pilot training simulator. Windows and macOS. Make in India.
    Public.      Do NOT let it add a README or .gitignore (you already have them).
    Topics (Settings, after creating): drone, rpto, dgca, simulator, flight-simulator,
            make-in-india, drone-training, india

STEP 2 - PUSH THIS FOLDER
  Open a terminal in this "github" folder and run:

    git init
    git add .
    git commit -m "Drone Trainer V2 - Windows and macOS"
    git branch -M main
    git remote add origin https://github.com/YOUR-USERNAME/drone-trainer-v2.git
    git push -u origin main

  (Replace YOUR-USERNAME and the repo name with yours.)

STEP 3 - CREATE THE RELEASE WITH THE DOWNLOADS
  On the repo page: Releases -> Draft a new release.
    Tag:   v2.2.0        (choose "Create new tag" -> v2.2.0)
    Title: Drone Trainer V2.2.0
    Notes: a short line, e.g. "Windows and macOS. Free to play. Advanced launches this Diwali."
    Attach these two files (drag them in). Keep the names EXACTLY as below so the
    README download buttons work:
       DroneTrainerV2-Setup.exe      (from the V2 folder, one level up)
       DroneTrainerV2-mac.dmg        (from V2\macOS)
    Publish release.

  That's it. The README buttons link to .../releases/latest/download/<file>, so they
  always point to your newest release.

NOTE ON FORKING
  People can fork the repo, but a fork only copies the README, the license and the
  screenshots - not the game. The game lives in the Release downloads, which are
  the protected builds. Advanced stays locked without a serial from you.

TIP
  If you would rather keep the code in a PRIVATE repo for your own backup, make a
  SECOND, private repo for that and keep this public one for downloads only. Never
  put licensing-private in either.
